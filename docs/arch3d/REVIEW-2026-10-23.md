# arch3d review — round 9 (2026-10-23)

Senior review of everything `arch3d` adds over `main` (phases 0–1 complete, phase 2 in
progress), before later phases build on it. Scope: `git diff main...arch3d` at `07b7a30`
(82 files, ~10 kLOC). Method: read every added file, built and ran the whole workspace, then
wrote a failing test for each bug before fixing it.

This file has two parts:

1. **Fixed in this PR**: what changed and the test that guards it. Each guard test was run
   against the original code and fails there.
2. **Open findings for the swarm**: problems in files this review was told not to touch
   (the phase-2 files), or that need a design decision. Each has a severity, `file:line` (at
   `07b7a30`), what breaks, and a suggested fix. **Critical** = wrong output, data loss or a
   check that passes without testing anything; **Important** = a real bug or a gap later
   phases will trip over; **Minor** = cleanliness, drift, small hazards.

## 2. Open findings for the swarm

### Critical

**C1. The 3D view still renders nothing.**
`render3d/src/pipeline.rs` (whole file), `render3d/src/offscreen.rs:Offscreen::render`, and
`ui-egui/src/pane3d.rs` (`available` is never set; there is no paint callback).
- **What breaks:** There is no `RenderPipeline`, no WGSL, no depth texture and no draw call. DESIGN
  §"Viewport" ("offscreen colour+depth targets, orbit camera … presented as an image") and the
  phase-1 "06 PASS" describe code that does not exist. After F16 the CLI says so honestly instead of
  writing a black PNG. The 3D pane is a text label.
- **Suggested fix:**
  - Add a `Depth32Float` target and a pipeline with the 40-byte vertex layout from
    `pipeline::upload`.
  - Upload `transpose(proj * view)` (now correct, see F17) as a uniform, and use flat Lambert from
    the normals (after fixing C3).
  - Clear to white, and present into the pane through `egui_wgpu::Callback` or a registered
    texture.
- **Test changes:**
  - Acceptance 06 (locked) should also require that the image is not uniform. For example, at
    least two distinct grey levels among the shaded pixels; today a constant colour passes.
  - Add a render3d test that renders one box and checks the centre pixel differs from the corner,
    skipping on `NoAdapter`.

**C2. Exported GLB files are invalid glTF.**
`io/src/glb.rs:165,219` write the attribute `"TEXTURE_COORDS_0"`.
- **What breaks:** glTF 2.0 names it `TEXCOORD_0`, and application-specific semantics must start
  with `_`. Validators report an error, and three.js and Blender drop the UVs.
- **Suggested fix:** Rename it. Add a GLB test that checks every attribute key against the
  spec's list.

**C3. Wall side faces have floor/ceiling normals.**
`arch3d/src/mesh.rs:141-174` (`push_prism`).
- **What breaks:** The side quads reuse the cap vertices, so every vertical face carries normals
  of (0,0,±1). Every viewer of the exported GLB lights walls as if they were floors. Any shading
  in C1 will do the same.
- **Why tests miss it:** `outward_normal` (line 179) was written for this and is dead code.
  `normals_face_outwards` (line 329) cannot catch it, because ±Z normals also have a non-negative
  dot product with "vertex minus centroid".
- **Suggested fix:**
  - Emit four vertices per side quad with `outward_normal`.
  - Make `is_manifold` weld by position (or compare positions, not indices).
  - Change the test so each triangle's geometric normal (cross product) must match its vertices'
    normals.

### Important

**I1. Proxy handles can collide with real entity handles.**
`doc/src/arch.rs:56` (`is_arch_handle`), routing in `engine/src/grips.rs:520,552`,
`cmd/gripcmds.rs`, and selection and pick.
- **What breaks:** The arch range is `0xA000_0000 .. 0xA000_0000+2^32`. DXF handles are arbitrary
  64-bit hex, and the reader bumps `handseed` past the largest handle in the file. Any real
  entity with a handle in that range gets grip-edited as wall `wN` (or "no such object").
- **Suggested fix:** Pick one of these:
  - Move the reserved range to the top of `u64` (`0xFFFF_FFFF_0000_0000 + id`) and make
    `bump_handseed` / handle allocation skip it.
  - Remap colliding entity handles on read.

  Add a test that reads a DXF with a LINE at handle `A0000001`.

**I2. Scene bounds always include the origin.**
`arch3d/src/mesh.rs:20` (`Bounds3::empty()` is a zero box at (0,0,0)), used at
`arch3d/src/lib.rs:59,85`.
- **What breaks:** A house at (500, 300) reports bounds from the origin to the house.
  `Orbit::fit` frames empty space, and `build3d`'s `bounds` are wrong.
- **Suggested fix:** Make `empty()` inverted (`+∞`/`−∞`) with an `is_empty()`, and have
  `build3d` print zeros only for a truly empty scene.

**I3. `build_dirty` trusts the dirty set and re-solves everything.**
`arch3d/src/lib.rs:68-91`.
- **What breaks:** Joins are re-solved for the whole model (so the only saving is extrusion), yet
  any wall not in `dirty` keeps its old mesh even when its *join* changed. Example: a T stem
  whose host was stretched, where `stretch_wall` only reports walls whose endpoints moved. Not
  wired to the pane yet, so the bug is latent.
- **Suggested fix:** Pick one of these:
  - Keep the solved polygon (or a hash) beside each cached mesh and rebuild whenever it differs.
    This is cheap, because the solve already happened.
  - Expand `dirty` through the graph and T hosts.

**I4. Walls ignore their level.**
`arch3d/src/lib.rs:54,80` hard-code `level_elevation = 0.0` and ignore `base_level` and
`to_ceiling`.
- **What breaks:** Phase 3 (levels) builds on this.
- **Suggested fix:** Look up `model.level(w.base_level)`, and use `ceiling_height` when
  `to_ceiling` is set.

**I5. Stretching a wall's start moves its openings.**
`engine/src/cmd/arch/stretch.rs` and `arch/src/join.rs::stretch_wall`.
- **What breaks:** `Opening::offset` is measured from the wall start. Stretching the *start* end
  shifts every opening along the wall. Shortening a wall can leave openings past its end, and
  nothing re-validates them. DESIGN §Phase 2 says "stretching the host wall keeps the opening in
  place", which is only true for the end grip.
- **Suggested fix:** When `start` moves, add the projection delta to each hosted opening's offset.
  Then run `validate_placement` for each one and either refuse the drag or apply `fit`.
- **Why it is left open:** This is a phase-2 semantic decision.

**I6. DXF payload versioning loses data in both directions.**
`io/src/dxf_arch.rs:58` (`parse_arch` rejects `version != 1`) and `:45`, `:92` (nothing is
written when the model has no walls).
- **What breaks:** DESIGN says phase 2 writes version 2 "accepting 1". Old builds reading v2 lose
  the model (after F15 they at least keep the proxy linework). A model with levels, types or
  openings but no walls is not saved at all.
- **Suggested fix:**
  - Accept `1..=CURRENT`, and keep unknown fields with `#[serde(flatten)] extra`.
  - Write the record whenever the model differs from `ArchModel::default()`.
  - Cap `openings.len()` at `MAX_OPENINGS` like walls.

**I7. Proxy polylines are raw rectangles.**
`io/src/dxf_arch.rs:71-85` (`wall_ring`).
- **What breaks:** Other programs see overlapping rectangles at every corner instead of the
  mitred poché, and no opening gaps.
- **Suggested fix:** Write `solve_joins` rings (and later the opening-cut outline).

**I8. Plan poché ignores the A-WALL layer state and draws no bands.**
`render/src/arch.rs:21-91`.
- **What breaks:** Walls stay visible with A-WALL off or frozen, and print with it set to no-plot.
  DESIGN ("including per-layer bands") and README describe bands that are never drawn.
- **Suggested fix:** Skip when the layer is off or frozen (and `plot = false` when plotting), and
  draw `wall_layer_polygons` bands, which are safe after F7.

**I9. Grip editing in `grip_edit` has the F13 bugs and skips the lock check.**
`engine/src/grips.rs:524`.
- **What breaks:** Grip index ≥ 2 is treated as "end". The locked-layer check that ordinary
  entities get (`curves::is_locked`) is skipped for walls.
- **Suggested fix:** Mirror F13 (refuse index > 1), and refuse when A-WALL is locked (in both
  `grip_edit` and `gripcmds`).

**I10. `arch.sample` leaves the model inconsistent.**
`engine/src/cmd/arch/sample.rs:98`, `:68`, `:51`.
- **What breaks:**
  - It replaces `walls` but keeps `next_id` (0) and any `openings`. Sample ids are 1..N, so the
    next `wall` command creates w0 and then a **duplicate w1**.
  - The retry loop reads `|| tried < 32`, so it always draws 32 numbers per wall (it should be
    `&&`).
  - It is `noundo` although it mutates the document, so a later undo of an earlier command
    silently discards the sample too.
- **Suggested fix:**
  - Set `next_id = n + 1` and clear `openings`.
  - Change `||` to `&&`.
  - Make it undoable.

**I11. `arch.inspect` reports a wrong join count.**
`engine/src/cmd/arch/inspect.rs:71`.
- **What breaks:** `joins` is `shapes.len()` (one per solved wall), not the number of joins.
- **Suggested fix:** Use `shapes.iter().map(|s| s.joins.len()).sum()`, as `wall` now does (F14).

**I12. Every new drawing gets five arch layers.**
`doc/src/lib.rs:171-175`.
- **What breaks:** A blank AutoCAD-parity drawing now carries A-WALL, A-DOOR, A-GLAZ, A-ROOF and
  A-STAIR. DESIGN decision 9 says arch3d is additive. `engine/tests/templates.rs` and
  `io/tests/pdf_layers.rs` were edited to accommodate the change, rather than the change being
  questioned.
- **Suggested fix:** Create the layers on first use: `wall` now adds A-WALL when it is missing
  (F14), and phase 2's `door`/`window` can do the same. Then drop them from `Drawing::new`.
- **Why it is left open:** It changes a template-level default, so it is the lead's decision.

**I14. The join solver is still quadratic and runs on every redraw.** (F25 adds a box prefilter, so the inner work is now cheap; the scan itself is still O(n²).)
`arch/src/join.rs` `classify`.
- **What breaks:** Every wall end scans every wall three times (Mid, X, Parallel), so each solve
  is O(n²). `render/src/arch.rs:24` solves on every display-list build. `inspect`, `build3d`,
  GLB export and now `wall` (to count joins) solve too. Near `MAX_WALLS` that is about 10⁸ checks
  per redraw.
- **Suggested fix:**
  - Reuse the F8 cell grid (cell = max thickness) to find Mid/X/Parallel candidates.
  - Cache the solved shapes keyed on `arch_revision`, for example in the render cache.

**I15. Y-junctions and other multi-way fans are still approximate.**
`arch/src/join.rs` `plan_end`.
- **What breaks:** Three or more non-collinear ends at one point (a Y) each mitre against their
  lowest-id neighbour only, so the rings overlap and leave small notches. F4 handled the common
  straight-through tee.
- **Suggested fix:** For a cluster of k ends, sort the ends by angle and mitre each one with its
  angular neighbours (left face with the next wall clockwise, right face with the previous one).

**I16. Hostile coordinates that are finite in f64 but not in f32.**
`arch3d/src/mesh.rs:143,149`.
- **What breaks:** `p.x as f32` on a finite 1e300 gives `inf`. The GLB accessors' `min`/`max` then
  serialise as `null`, which makes the file invalid. `push_prism` only checks `f64::is_finite`.
- **Suggested fix:** Skip (or error on) a ring whose `f32` cast is not finite, and add it to
  the hostile tests. Better still, extrude relative to a local origin; that also fixes f32
  precision loss for georeferenced plans.

**I17. Two sources of truth for a wall's build-up.**
`doc/src/arch.rs` `Wall::layers` vs `WallType::layers`; also `engine/src/cmd/arch/mod.rs:36`
(interior stud 0.09) vs `doc/src/arch.rs:429` (0.074).
- **What breaks:**
  - Each wall copies its bands, so editing a type changes nothing.
  - `wall` stores `wall_type` as "exterior", "interior", "knee", "railing" or "retaining", but

**I18. GLB is Z-up; glTF is Y-up.**
`io/src/glb.rs:227-231` (nodes).
